# 复合肥配方推荐工具：产品需求基线

更新时间：2026-08-20

## 1. 产品定位

这是一个面向复合肥配方人员的配方推荐工具。用户输入目标配合式、工艺和控制指标，系统从原料库中生成满足养分、氯离子、水溶磷、原料数量及用户指定原料条件的候选配方，并按实际成本由低到高展示最优的 3 个结果。

主要使用场景是微信内置浏览器，后续需要支持同一个微信用户在不同设备上访问同一套原料和配方数据。

## 2. 页面与交互

### 2.1 推荐配方页

- 页面分为“推荐配方”和“原料维护”两个选项卡。
- 工艺是计算参数，不是页面路由。仅切换工艺时，目标参数和已有推荐结果都不能变化；只有点击“生成推荐”才重新计算并输出结果。
- 修改目标值、优先下调养分、必选原料和更多指标时，不自动计算。
- 点击“生成推荐”后显示页面遮罩、居中 loading 动画和文案“配方生成中，请稍等”，避免用户误认为页面卡死。
- 配合式只允许整数输入；水溶磷比例只允许整数输入；总养分由配合式自动计算并禁止手动修改；数字输入框不显示加减按钮。
- 原料数量上限提供 1-6 种选项，算法不得使用超过该数量的原料。
- 算法支持 1-6 种原料上限；1-3 种原料使用整数配比搜索，4-6 种原料使用带预算的约束求解。若原料本身无法覆盖目标养分或指标约束，应返回“没有找到满足条件的配方”，不能把原料数量下限误报为系统错误。

### 2.2 目标参数

- 配合式：N-P-K。
- 原料数量上限：1-6。
- 总养分下限：按配合式自动显示。
- 单养分安全下调：控制单一养分允许低于目标的范围。
- 优先下调养分：N、P、K 各有一个优先级下拉框，选择顺序代表下调优先级；未设置时沿用原算法。
- 氯离子等级：硫基、低氯、中氯、高氯。
- 水溶磷比例：转鼓和挤压工艺均支持该指标，使用同一套水溶磷约束、求解和结果展示逻辑。
- 成品水分、加工费用：按工艺提供默认值，也允许在目标区域调整。

### 2.3 必选原料

目标区域内有单独底色的“必选原料”区域，包含磷源、氮源、钾源三个下拉多选框。

- 勾选的原料必须出现在推荐配方中。
- 勾选原料数量超过原料数量上限时，不开始计算，弹出 toast：`必选原料数量超过原料数量上限，请重新配置`。
- toast 默认显示 3 秒，点击页面背景可以提前关闭。
- 勾选状态的变化只修改待计算参数，不直接更新推荐结果。

### 2.4 推荐结果

- 结果按实际成本由低到高排序。
- 生成阶段也必须优先搜索低价组合，不能只在生成完成后对随便找到的结果排序。
- 最终显示成本最低的 3 个有效配方。
- 配方卡片先展示主要信息：实际成本、总养分、用户填写的主要控制指标。
- 产出率、标准成本、PH 值等属于次要信息，不与主要指标同级突出展示。
- 明细信息默认折叠，折叠按钮必须有明确箭头/展开收起交互，用户能看出可以点击。
- 点击配方中的原料，打开该原料主要信息：价格、N-P-K、水分、氯离子；N、P、K 和水分显示整数。
- 明细页可直接修改原料参数，保存后同步到原料数据，并影响后续推荐计算。

## 3. 氯离子业务规则

含氯原料主要是氯化铵和氯化钾。它们分别是氮源、钾源中成本较低的原料，因此在满足氯离子限制的前提下，应尽量使用到安全范围附近，而不是输出远低于目标等级的结果。

### 3.1 目标范围

以下是当前确认的产品规则：

| 等级 | 有效氯离子范围 |
| --- | --- |
| 硫基 | 小于 3% |
| 低氯 | 13% - 14.5% |
| 中氯 | 27% - 29% |
| 高氯 | 大于 30% |

低氯和中氯是闭区间；硫基和高氯保留原有开区间语义。

### 3.2 算法要求

- 低氯和中氯必须作为硬约束，不能先生成一个氯离子为 9% 的低成本配方，再把它当作中氯结果。
- 在有效范围内，仍以实际成本最低为第一排序条件。
- 成本相近时，可以优先选择更接近范围边界但保留生产安全距离的方案；不能为了追求某个指标而破坏成本第一原则。
- 水溶磷和单一养分下调采用相同思路：用户设置的是目标/下限，算法需要在满足安全范围的前提下寻找成本最低的组合，而不是简单从已经生成的结果中筛选。
- 典型验证场景：20-8-10、最多 5-6 种原料、必选氯化铵、水溶磷 60%，应允许类似“尿素 + 氯化铵 + 硫酸铵 + 55 一铵 + 滤饼 + 60% 氯化钾”的组合进入候选，并验证其养分、水溶磷、氯离子和成本。

## 4. 原料维护

- 原料按氮源、磷源、钾源、微量元素、辅料/填充、返料分类维护。
- 列表只展示常用字段，完整参数在编辑详情页维护。
- 名称、类别、单价、是否参与推荐为必填项，显示红色星标。
- 类别只能从已有类别下拉选择，不能自由输入。
- 保存时校验必填项；缺少必填项时弹出 toast：`请输入必填项`，对应输入框显示红色边框。
- 镁、钙、有机质、硼、锌、水不溶物、PH 值属于高级参数，编辑页默认折叠；主要参数默认直接显示。
- 当前数据修改保存到浏览器 `localStorage`，这只是过渡方案，不能满足跨设备和微信用户隔离要求。

## 5. 用户数据与账号目标

产品最终不是全局共享原料库，也不是依赖浏览器缓存，而是每个微信用户拥有独立数据集。

- 微信用户身份应使用 `openid` 作为当前公众号/应用范围内的用户唯一标识；`appid` 是应用标识，不是用户标识。
- 如果未来需要跨多个微信应用识别同一用户，再评估使用 `unionid`。
- 用户的原料、目标设置、必选原料、推荐历史都必须按用户隔离。
- 前端不能直接连接数据库，也不能由前端传入的 `userId` 决定数据权限。

## 6. 暂不确定事项

- 1-3 种原料采用整数配比搜索，搜索范围和页面响应时间仍需结合真实原料规模持续压测。
- 挤压原料的水溶磷基础数据仍需按实际原料检测值补齐；算法规则与转鼓一致。
- 单一养分下调的安全上限、总养分上限和生产误差，需要和实际生产标准再次确认。
- 推荐算法是否要求数学意义上的全局最优。如果要求全局最优，计算应放到后端 worker，不应继续依赖浏览器主线程的有限搜索。
